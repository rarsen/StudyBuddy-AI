# 1. Project overview

## 1.1 Problem

Most students prepare for exams by re-reading slides and highlighting. Learning research rates both as low-value techniques.

The two techniques rated most effective are practice testing and spacing reviews out over time (Dunlosky et al., 2013). The "testing effect" (being quizzed improves long-term memory) is well established (Roediger & Karpicke, 2006).

Writing good practice questions and flashcards by hand takes hours, so few students do it.

Cloud AI tools can generate this material, but they have three drawbacks:
- Course materials and personal notes must be uploaded to a third party, and lecture slides are often copyrighted.
- You pay, or hit limits, once you go past the free tier.
- They only work with an internet connection.

## 1.2 Product

**MindSpark** turns a student's own lecture PDFs into active study material:

1. **Library.** Upload PDFs. The app splits them into chunks and indexes them for meaning-based (semantic) search.
2. **Practice.** Generate a multiple-choice quiz from a document. Every question comes with an explanation and a page citation.
3. **Review.** Flashcards are generated automatically and scheduled into a daily review queue with spaced repetition. The scheduling algorithm is FSRS.
4. **Ask.** Chat about the material. Answers cite pages, and the app says plainly when something isn't in your notes.
5. **Progress.** See how many cards are due and your accuracy per document.

Two editions share one codebase:

| Edition | Runs the AI | Database | Purpose |
|---|---|---|---|
| Web (existing Render deployment) | Cloud LLM (OpenAI) | PostgreSQL | Access from anywhere. Also the **cloud baseline** for the thesis evaluation |
| macOS app | Local LLM (llama.cpp's `llama-server`, on the Mac's GPU via Metal) | SQLite | Free, private, works offline |

## 1.3 Target users

- **In scope:** university students who have lecture PDFs and are preparing for exams. They are also easy to recruit as testers (classmates).
- **Out of scope for now:**
  - Middle- and high-school students. Minors bring extra consent, safety and data-protection requirements.
  - Researchers. A research assistant is a different product.
  - Non-English users. See [future work](05-future-work.md#4-ukrainian-language-support).

## 1.4 Why a local LLM fits this problem

- **It plays to small models' strengths.** Small models (2–9 billion parameters) often invent facts when asked open-ended questions. But they are decent at "read this passage and write questions about it", which is close to a reading-comprehension task. The product is built around this kind of grounded generation from the student's own text.
- **Privacy.** Course materials and notes never leave the laptop.
- **No cost per use.** Students get unlimited quizzes with no subscription. The developer pays nothing for inference either, unlike an app wrapping a paid API, which pays for every message.
- **Offline.** Students can study anywhere.

## 1.5 Competition and positioning

Cloud tools such as NotebookLM and Quizlet already generate study material from uploaded files.

MindSpark's position: **it runs on the device, is free and works offline, has spaced repetition built in, and every item carries a page citation.** The thesis must address this comparison directly.

## 1.6 Current codebase (baseline commit `0571b32`)

### Tech stack

- **Backend:**
  - Python, FastAPI 0.109, SQLAlchemy 2.0 (synchronous).
  - PostgreSQL 15 with the pgvector extension.
  - OpenAI SDK 1.10, pypdf, tiktoken.
  - python-jose (JWT tokens), passlib/bcrypt (password hashing).
  - Entry point: `backend/app/main.py`.
- **Frontend:**
  - React 18, Vite 5, TailwindCSS 3.
  - axios, react-router 6, react-markdown 9.
  - English/Ukrainian interface translation and a dark theme.
- **Infrastructure:**
  - `docker-compose.yml` runs the database, backend, frontend and pgAdmin.
  - `render.yaml` is the deployment blueprint for Render.

### Architecture (as-is)

```
React SPA (5173) ──HTTP──► FastAPI (8000) ──► OpenAI API (chat + embeddings)
                                         └──► PostgreSQL + pgvector
```

### Implemented features

- **Accounts:** registration and login with JWT tokens, plus a profile page.
- **Chat:** sessions with history and a subject context. Session titles are generated by the model.
- **Document upload (PDF/TXT/MD):**
  1. Extract the text.
  2. Split it into 400-token chunks, overlapping by 80 tokens.
  3. Embed each chunk with OpenAI (1536-dimensional vectors).
  4. Store the vectors in pgvector.
- **Retrieval before generation:**
  - The top 5 chunks by cosine similarity (minimum score 0.25) are fetched before the model answers.
  - Sources are numbered `[n]`. Any citation number the model invents is stripped out (`sanitize_citations`, `backend/app/services/ai_service.py:271`).
- **Mock mode:** canned responses and embeddings when no API key is set. CI and demos never touch the network.

### Designed but not built yet (a head start for the MVP)

- **Flashcards:** tables with the fields FSRS needs, `Flashcard` and `FlashcardReview` (`backend/app/db/models.py:209-264`). No service or endpoints yet.
- **Quizzes:** tables for multiple-choice, short and open questions with a grading rubric, `Quiz`, `QuizQuestion` and `QuizAttempt` (`models.py:270-340`). No service or endpoints yet.
- **Tools:** an abstraction for OpenAI-style function calling (`backend/app/services/tools/base.py`). No tools are registered.
- **Code execution:** `sympy` is listed in the requirements but never used. `CODE_EXEC_*` settings exist (`backend/app/core/config.py:57-58`), but there is no sandbox.
- **Tests:** `pytest.ini` points to a `tests/` folder that does not exist.

### Audit findings

These issues start to matter as soon as the AI runs locally or offline.

| # | Finding | Location | Impact | Fix in |
|---|---|---|---|---|
| 1 | OpenAI client is created without `base_url` | `backend/app/services/ai_service.py:106`, `backend/app/services/embedding_service.py:62` | Good news: setting `base_url` connects any OpenAI-compatible local server | M1 |
| 2 | A blocking (synchronous) OpenAI call sits inside an `async def`. Document ingestion has the same problem | `ai_service.py:217`, `backend/app/services/rag_service.py:181` | The whole API freezes for as long as generation or ingestion runs | M1 / M2 |
| 3 | No streaming and no cancel button | `frontend/src/pages/Chat.jsx:109` | Local models produce 15–40 tokens/s, so long answers mean a long spinner | M1 |
| 4 | A database transaction stays open during the LLM call | `backend/app/services/chat_service.py:176-238` | SQLite allows only one writer at a time, so every other write is blocked until generation finishes | M1 |
| 5 | Retrieved sources are placed inside the **system** prompt | `ai_service.py:118-129` | The start of the prompt changes on every turn, so llama.cpp cannot reuse its prompt cache and reprocesses the whole history each time. Locally, this dominates the wait before the first word appears | M1 |
| 6 | The title model `gpt-4.1-nano` is hard-coded | `ai_service.py:248` | Title generation fails with a local model | M1 |
| 7 | Embedding size is fixed at `Vector(1536)` | `models.py:194`, `config.py:47` | Local embedding models produce 384–1024 dimensions | M1 |
| 8 | `tiktoken.get_encoding` runs when the module loads | `rag_service.py:35` | It downloads a tokenizer file on first run. Offline, chunking silently falls back to estimating tokens as length/4 | M1 |
| 9 | Startup runs Postgres-only SQL (`CREATE EXTENSION`, `jsonb`, `ADD COLUMN IF NOT EXISTS`) | `backend/app/main.py:47-88` | The app cannot start on SQLite | M1 |
| 10 | `/debug/config` returns the first 15 characters of `SECRET_KEY`, and the `DEBUG` setting does not turn it off | `main.py:100-112` | Part of the secret key is exposed in production today. On desktop, any local process or web page could read it. **Delete immediately** | M0 |
| 11 | Google Fonts are loaded from Google's servers | `frontend/index.html:9-12` | Fonts break offline, and there is a GDPR risk (LG München I, 2022). Bundle the fonts with the app instead | M3 |
| 12 | No tests | `backend/pytest.ini:2` | Nothing catches regressions during the refactor | M1 |
| 13 | Mock mode is switched on by guessing from what the API key string looks like | `ai_service.py:28-39`, `embedding_service.py:23-31` | Fragile. Replace it with an explicit `LLM_PROVIDER` setting | M1 |
| 14 | The API address is `VITE_API_URL \|\| 'http://localhost:8000'` | `frontend/src/services/api.js:3` | An empty value falls back to localhost:8000, so the desktop build, where frontend and API share an origin, needs special handling | M3 |
